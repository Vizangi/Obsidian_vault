
- 1. делаем папку

```bash
mkdir -p ~/monitoring-course/03-node-exporter
cd ~/monitoring-course/03-node-exporter
```

- 2. системный юзер

```bash
sudo useradd --no-create-home --shell /bin/false node_exporter
```

- 3. качаем бинарник

```bash
cd /tmp
NE_VERSION=$(curl -sL "https://api.github.com/repos/prometheus/node_exporter/releases/latest" | grep -oP '"tag_name": "\K[^"]+')
echo "Ставим Node Exporter $NE_VERSION"
wget -q "https://github.com/prometheus/node_exporter/releases/download/${NE_VERSION}/node_exporter-${NE_VERSION#v}.linux-amd64.tar.gz"
tar xf node_exporter-${NE_VERSION#v}.linux-amd64.tar.gz
cd node_exporter-${NE_VERSION#v}.linux-amd64
ls -la    # должен быть только node_exporter (бинарник)
```

- 4. Раскладываем

```bash
sudo cp node_exporter /usr/local/bin
sudo chown node_exporter:node_exporter /usr/local/bin/node_exporter
node_exporter --version  # проверка бинарника, что он рабочий
```

- 5. Systemd-unit (в репо!)

Создаем 03-node-exporter/node_exporter.service:

```ini
[Unit]
Description=Node Exporter
Wants=network-online.target
After=network-online.target

[Service]
User=node_exporter
Group=node_exporter
Type=simple
ExecStart=/usr/local/bin/node_exporter \
    --collector.systemd \
    --collector.processes
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

- `--collector.systemd` — собирает метрики по systemd-сервисам (какие запущены, какие упали)
- `--collector.processes` — собирает метрики по процессам (сколько всего, сколько в разных состояниях)
без этих флагов Node Exporter работает но часть метрик не отдает

деплоим:

```bash
sudo cp ~/monitoring-course/03-node-exporter/node_exporter.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now node_exporter
sudo systemctl status node_exporter --no-pager | head -5
```

- 6. Проверки
```bash
curl -s http://localhost:9100/metrics | head -20
sudo ss -tlnp | grep **9100**
```


- 7. Добавляем job в Prometheus

```yaml
scrape_configs:
  - job_name: "prometheus"
    static_configs:
      - targets: ["localhost:9090"]

  - job_name: "node"
    static_configs:
      - targets: ["localhost:9100"]
        labels:
          instance: "master"
```

деплой и релоад:

```bash
sudo cp ~/monitoring-course/01-prometheus/prometheus.yml /etc/prometheus/
sudo chown prometheus:prometheus /etc/prometheus/prometheus.yml
sudo -u prometheus promtool check config /etc/prometheus/prometheus.yml
curl -X POST http://localhost:9090/-/reload
```

- 8. Проверка в Prometheus UI

Браузер: **http://master:9090** → **Status → Targets**

Должно быть два таргета:

- `prometheus` (localhost:9090) — UP
- `node` (localhost:9100) — UP

Если `node` = DOWN — смотри в Prometheus UI → **Status → Targets** → кликни на `node` → **Last Error** покажет, что не так.

- 9. Первый запрос к Node Exporter

В Prometheus UI → **Graph** → вбей:

```
node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes * 100
```

Это процент доступной памяти. Execute → увидишь число около 60-80%.
